# Bluewhale 工程日志 2026-09-01

## 本轮更新

- 明确的“打开/启动应用”请求先由 Kotlin 匹配已安装应用并执行 `Launch`，桌面搜索降为回退路径。
- 增加设备 Profile：厂商、型号、SDK、物理尺寸、density、旋转和系统安全边距。
- VLM 全图最长边由 1920 提升到 2560，改善小图标细节。
- `ScreenCapture` 增加 frame id、采集时间、新鲜度和来源。
- 无障碍树已经变化但虚拟屏仍返回缓存帧时，拒绝把矛盾观察发送给 VLM。
- 视觉 Tap 只有目标描述与节点语义匹配时才吸附；“搜索结果”不能吸附到可编辑输入框。
- 新增跨 Tap/Type/Wait 的混合无进展检测：4 步告警、8 步终止。
- 对话路由对空内容、纯文本和坏 JSON 进行稳定降级。
- AgentService 增加 run generation；新任务等待旧任务取消和平台清理，旧任务不能回写新状态。
- 常驻通知显示 Step、阶段、状态和验证摘要；支持 RemoteInput 输入命令、停止当前任务、重试上次任务与保留语音入口。
- 电脑监视器新增 frame freshness/source 与 no-visual-progress 字段。
- AgentGraph 新增显式 REFLECT 节点：连续目标点击失败会先反思并强制更换定位策略；即使每一步验证成功，也会识别 A→B→A→B 两状态循环。
- 反思层维护页面-动作禁止表；模型再次提出已被否定的组合时不会执行，而是重新进入反思。
- 已验证的 Type → 发送 会登记文本摘要；相同文本再次输入或没有新文本时再次点击发送会被 Kotlin 拒绝。
- function-calling 动作增加 reason 与 expected_outcome，电脑端默认显示“依据 / 动作 / 预期 / 执行 / 验证 / 反思”。
- monitor-agent.ps1 默认改为精简视图；-VerboseTrace 查看全字段，-OutputPath 继续保留完整 JSONL。
- 2.5.0 接入官方 Vosk Android 0.3.75 与 Apache-2.0 中文小模型；主页面使用可见录音面板，通知栏在首次授权后使用独立 microphone 前台服务后台收音，识别文本自动进入聊天/任务路由。
- `Take_over` 改为保留虚拟 Display 并等待明确同意；同意后通过 Shizuku `moveRootTaskToDisplay` 迁移当前可见 root task 到物理屏，迁移失败保留现场供重试。
- “打开/启动/进入应用”且没有后续动作的虚拟屏任务，在 Launch 后置验证通过后直接进入等待接管；复合任务不触发。
- 动作失败预算、Tap 定位耗尽、Wait 卡死和混合无进展不再直接硬熔断，而是转入 Reflection；恢复连续失败后调用仅允许 `Take_over` / `complete_task` 的终局裁决模型。
- v2.0 发布线新增封闭的 `SystemCapability` 工具层：导航、闹钟、计时器、日历、联系人、短信/邮件撰写、拨号准备、相机、网页/搜索、系统设置、分享与媒体播放。
- 模型只输出强类型字段，不能提供 Intent action、component 或 shell 命令；校验层限制枚举、长度、URL scheme 与 ISO-8601 时间，执行器由 Kotlin 构造固定 Android Intent。
- 中风险工具只打开系统预填/确认界面；在虚拟屏分发成功后进入 `Take_over`，保留现场供用户确认迁移。删除、静默发送和直接拨号等高风险能力未开放。
- 会话路由已识别导航/闹钟/日历等明确请求；关键时间或对象缺失时要求先聊天追问。规划上下文增加手机当前本地时间。

## 已知边界

- 通知命令依赖无障碍服务仍处于连接状态以及系统通知权限。
- ColorOS 可能需要展开通知后才显示内联输入框。
- 首次语音输入需要联网下载约 42 MB 模型；当前 Debug APK 因包含 Vosk 多 ABI 原生库约 97 MB，后续发布可按 ABI 拆包。
- root task 迁移使用 Android 隐藏 API，AOSP Android 12 至当前主线均存在该接口，但仍需对每个厂商 ROM 做接管回归。
- 缓存帧与新语义冲突时当前选择失败关闭，不继续盲目点击；后续可增加虚拟屏原生截图的第二后端。
- 设备型号只用于显示变换和安全边距，不假设固定桌面图标位置。
- **暂缓：长文本 function arguments 被截断。** 2026-09-01 测试中，约 1193/1194 字符处出现 Unterminated string。现象更符合 max_tokens=768 或 Provider 输出上限截断，而非输入上下文本身溢出；按当前决定只记录，暂不提高生成预算、拆分长文本或增加流式续写。
