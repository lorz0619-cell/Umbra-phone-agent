# Umbra phone-agent v2.0.0

Umbra 2.0 replaces the AutoGLM runtime with a Kotlin graph agent driven by a configurable
OpenAI-compatible multimodal model. It can operate the physical screen or an isolated Shizuku
virtual display.

## Highlights

- Kotlin graph runtime with explicit perception, planning, validation, execution, verification,
  reflection and routing nodes.
- Screenshot plus accessibility-tree perception and target-box/element-index Tap strategies.
- Structured actions: Launch, Tap, Type, Swipe, Back, Wait and Take_over.
- Stable Android system tools for navigation, alarm/timer, calendar/contact prefill, SMS/email
  composition, dialer, camera, web/settings, sharing and media.
- Per-subtask reflection budget: five recovery attempts before terminal adjudication.
- Virtual-display takeover confirmation, offline Vosk Chinese speech commands, conversational UI
  and actionable task notifications.
- Structured PowerShell log monitor for local debugging.

## Requirements

- Android 12 (API 31) or newer.
- Shizuku running and authorized for virtual-display mode.
- Umbra accessibility service enabled.
- A user-provided OpenAI-compatible multimodal model API key.
- Microphone permission for voice commands; the Vosk model downloads on first use.

## Security and privacy

- Source code is released under Apache License 2.0.
- Release builds contain no default API key. Users configure their own key in App settings.
- Release networking requires HTTPS and system-trusted certificates. Debug builds alone permit
  cleartext/local endpoints and user certificates for development.
- App data is excluded from cloud backup and device transfer.
- Release logcat output redacts task text, typed text, target descriptions, model reasoning and
  shell-command arguments.
- Medium-risk system tools open prefilled confirmation pages instead of committing external side
  effects automatically.
- The APK requests QUERY_ALL_PACKAGES because a general-purpose sideloaded agent must resolve
  arbitrary installed apps. This build is intended for GitHub sideloading, not Google Play.

## Known boundaries

- Virtual-display creation and task migration use Shizuku plus hidden Android APIs and therefore
  require device/OEM regression testing.
- The Provider key is stored in the app-private preferences on the device; rooted-device threat
  models require additional protection.
- Main-screen and virtual-screen text input still share Android's system IME infrastructure.
- Payment, login, CAPTCHA and other sensitive steps require Take_over.
