# Umbra phone-agent v2.1.0

## Summary

v2.1.0 is a reflection, virtual-display and benchmark-quality update over v2.0.0. The
release focuses on reducing false reflection triggers, making recovery more autonomous,
normalizing takeover behavior for all virtual-display tasks, and making the local benchmark
easier to run and audit.

## Highlights

- Reflection state now separates action success from subtask progress.
- Repeated no-effect actions trigger recovery:
  - repeated Wait
  - repeated Tap on the same normalized coordinate
  - repeated failed Type
- A visual change threshold of `0.25` releases repeat counters and blocked paths after a real
  page change.
- Recovery proposals include candidate paths such as adjusted coordinates, alternative nodes,
  Back/Swipe/Wait/Type options, and app-specific hints.
- A proposal novelty gate prevents the model from reusing a candidate that has already failed.
- Candidate attempts and reflection episodes are budgeted separately, so coordinate search no
  longer trips the ordinary action-failure fuse.
- All virtual-display task completions now enter a user-confirmed takeover flow instead of
  silently stopping or moving content.
- Virtual-display rotation is synchronized before perception and execution, and screen captures
  use the actual bitmap dimensions.
- App icon changed to a blue background with a white uppercase U.
- Settings page shows virtual-display preview at the top and version number at the bottom.
- Manual termination now shows “已终止任务” in the app and appends a matching assistant message.
- NetEase Cloud Music has a package-level hint: return to the home screen, then use the top
  magnifier/search entry instead of the bottom navigation search button.

## Reflection model

```text
PERCEIVE -> PLAN -> VALIDATE -> EXECUTE -> VERIFY -> ROUTE
                       ^                            |
                       |                            v
                    REPLAN <------------------- REFLECT
                       |
                       v
            candidate paths -> novelty gate -> execute or terminal
```

Local counters:

- `repeatedWaitCount`
- `repeatedTapCoordinateCount`
- `repeatedTypeFailureCount`
- `candidateAttemptsInEpisode`
- `lastCandidateFingerprint`
- `blockedTapCoordinates`

Release conditions:

- `visual >= 0.25` clears repeated counters and blocked paths.
- A subtask transition clears the current recovery scope.

## Known boundaries

The v2.0.0 Android, Shizuku and IME boundaries still apply. Notably:

- Virtual-display text input can still affect the main-screen IME.
- File-manager and OEM-browser behavior varies by device.
- Dynamic content tasks, such as daily recommendations and highest-viewed videos, require
  manual comparison against the current screen.
- Payment and login flows still require human takeover.
